# Where Microsoft Learn files each Win32 symbol

[WIN32-LEARN-MAP-DATA.txt](WIN32-LEARN-MAP-DATA.txt) is a dated record of the sections Microsoft Learn
documents Win32 symbols under, so that "which section does this belong to" is a lookup in a file. It
exists to apply the placement rule recorded in
[DESIGN-NOTES.md](DESIGN-NOTES.md#safe-wrappers-are-placed-by-the-learn-section-they-are-documented-under);
the rule is stated there and not here.

The file is generated by [tools/snapshot-learn-toc.ps1](tools/snapshot-learn-toc.ps1) from Learn's own
table of contents, and says in its first lines the day it was read, what it covers and what it does not.
It covers the areas under Develop > Desktop App Technologies, and the areas with no table of contents of
their own are named in its header.

## Reading it

A line starting `# ` is the path of section titles that reaches a list of symbols. Under it, each line is
`kind`, `header`, `name` and, only where Learn's name differs from its page address (the `A` and `W` forms),
`=slug`, separated by tabs. The kinds are `function`, `struct`, `enum`, `callback`, `interface`, `class`,
`method`, `delegate` and `control-code` (an `IOCTL_` or `FSCTL_` value).

## Classifying a symbol

1. Find the symbol: `Select-String -Path WIN32-LEARN-MAP-DATA.txt -Pattern '\tGetSecurityInfo$'` gives
   the line, and the `# ` line above it, the section.
2. A title can be shared by different symbols: Learn lists a callback titled `DuplicateHandle` under
   `ntsecpkg.h` and the function of that name under `handleapi.h`. Learn's pages convey meaning to people
   and a reader looks them up by title, so this is not an error and the record keeps it. The kind and
   header with the name identify the symbol; check them against the `windows-sys` binding the wrapper calls.
3. Take the second-level topic under the area (for `GetSecurityInfo`, *Authorization*; for
   `GetHandleInformation`, *Handles and Objects*), and look for a crate that already covers it.
4. **The record is a relation and not a function.** The same symbol can be listed under several sections,
   because the documentation puts it where a reader would look for it, and that is Learn doing its job
   and not a fault in it. The record keeps every listing and this recipe does not pick one for you: when a
   symbol is listed more than once, the placement is a judgement by meaning, and the crate's notes say
   which section was chosen and which others list it.

## Keeping it

Regenerate it with the tool when a symbol is looked up and is not there, or when Learn is known to have
reorganised; a regeneration is a commit on its own with the new date. The header and the section names it
records are Microsoft's and are not used in any crate name or public path, so a rename is a new snapshot and
never a release.
