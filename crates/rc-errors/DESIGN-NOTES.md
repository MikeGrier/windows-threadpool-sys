Current decisions for this component. What it is: [README.md](README.md). The work: [CHECKLIST.md](CHECKLIST.md), and
parked work in [PARKED.md](PARKED.md). The crate was decided in durable-ioring's
[DI-D-105](../durable-ioring/DESIGN-NOTES.md#di-d-105), which holds the engineer's rulings and the reasoning that led to
them; the conversation is the Tier 3 record,
[DESIGN-SESSION-2026-10-22-durable-ioring-no-std-and-preallocation.md](../../design-sessions/DESIGN-SESSION-2026-10-22-durable-ioring-no-std-and-preallocation.md#the-fault-report-without-the-global-allocator-continued-2026-10-23).
This component keeps Tier 1 only, with the rationale folded into each decision.

## Decision index

| ID | Decision |
|---|---|
| <a id="rce-d-1"></a>RCE-D-1 | **A shared error for `no_std` code that must not depend on the global allocator, and nothing broader.** Made for durable-ioring's fault reports ([DI-D-105](../durable-ioring/DESIGN-NOTES.md#di-d-105)), which may not allocate through the global allocator after construction, and which sit in a crate that forbids `unsafe`; this crate holds the `unsafe` instead, so the layer below carries it ([DI-D-4](../durable-ioring/DESIGN-NOTES.md#di-d-4)). Scoped to errors by the engineer's choice of two constructors (RCE-D-5): it is not a general replacement for `Arc`, and offers no sized `Shared<T>`. **Named `rc-errors`** in place of the engineer's proposed `durable-ioring-rc-errors-sys`, with his leave: `-sys` marks a thin unsafe Win32 wrapper in this workspace, and any `no_std` crate can use this one. |
| <a id="rce-d-2"></a>RCE-D-2 | **`no_std` with `alloc`, portable, and no dependencies.** `alloc` is needed only for `Global` (RCE-D-3); nothing else here allocates except through an allocator it is given. No `std` feature: an `io::Error` is an `Error + Send + Sync + 'static` and goes through the ordinary constructor, so `std` interop is the consumer's. CI's `portable` job builds, tests and lints the crate on Linux and macOS. |
| <a id="rce-d-3"></a>RCE-D-3 | **The allocator interface is a copy of the smallest part of the standard library's unstable `core::alloc::Allocator`:** the `unsafe trait Allocator` with `allocate` and `deallocate`, `AllocError`, and a `Global` over `alloc::alloc`, with upstream's names and signatures, so moving to the stabilised trait is a change of import (the engineer, in DI-D-105). Upstream has since split the trait (`AllocatorClone`, `AllocatorNightly`, `StaticAllocator` sit beside it); none of that is copied, and the methods the crate does not call (`grow`, `shrink`, `allocate_zeroed`, `by_ref`) are not either. The trait must stay usable as `dyn Allocator + Sync`, which the header needs (RCE-D-4). `Global` signals failure from `alloc::alloc::alloc`'s null and never calls `handle_alloc_error`. **`Refusing`**, an allocator that refuses everything, was added for durable-ioring's `DI-23.4.2`: a caller's fallback for a failed allocation is otherwise unreachable on demand, and a caller that forbids `unsafe` -- durable-ioring's tests among them -- cannot write such an allocator itself. |
| <a id="rce-d-4"></a>RCE-D-4 | **The shared error is one block, `#[repr(C)]`: a `u64` count, the allocator as `&'static (dyn Allocator + Sync)`, then the error.** No weak count, so dropping the error and freeing the block happen together when the count reaches zero, on whatever thread drops last, through the allocator recorded in the block. **The count is a `u64` with no overflow check** (the engineer: "use u64, they cannot overflow unless we're going beyond inc/dec"), so the crate needs 64-bit atomics. **The allocator pointer is fat**, 24 bytes of header on a 64-bit target, because it is the simpler code (the engineer: "whatever makes the code simpler"). **`repr(C)`** makes the layout the free computes with `Layout::for_value` from the `dyn` form the documented layout of the block that was allocated, where the default representation's agreement is not documented. **Ordering** follows the standard library's `Arc`: an increment is `Relaxed`, a decrement is `Release`, and the decrement that reaches zero is followed by an `Acquire` fence before the error is dropped and the block freed. The error's layout is read before it is dropped. |
| <a id="rce-d-5"></a>RCE-D-5 | **Two safe constructors and no others** (the engineer: "just do 1 and 2"). (1) A generic, fallible constructor taking any `E: Error + Send + Sync + 'static` and an allocator, with a variant using `Global`; it allocates the block for the concrete `E` and coerces the `NonNull` inside, where the target is fixed, so the result is the shared `dyn Error + Send + Sync` and no caller handles a pointer. On failure it returns the error with the `AllocError`, untouched. (2) A `const`-constructible static error (RCE-D-6). A consumer that wants the concrete error back downcasts through `dyn Error`'s own `downcast_ref`. Stable Rust gives no way for a type of ours to coerce implicitly or to be a `self` receiver for dynamic dispatch (`CoerceUnsized`, `derive(CoercePointee)` and `arbitrary_self_types` are unstable); `Error`'s methods take `&self`, reached through `Deref`, so neither is needed. |
| <a id="rce-d-6"></a>RCE-D-6 | **The static error holds a message and nothing else.** The assistant's, 2026-10-23, narrowing DI-D-105 as first written ("a message and an `ErrorCode`"), which was corrected to match: `ErrorCode` is durable-ioring's type, which this crate cannot name, and DI-D-105 already carries a refusal's code beside its report, in `IoFault`. A numeric code here would be a second, uninterpreted copy of that one. Raised with the engineer when recorded. |
| <a id="rce-d-7"></a>RCE-D-7 | **The report is an enum of the two forms**: a `&'static (dyn Error + Send + Sync)`, or the shared error. It is `Clone`, dereferences to `dyn Error + Send + Sync`, implements `Error` by delegating, and **compares by identity**: the static's address, or the shared block's, and never equal across forms (DI-D-105). The shared error compares the same way. |
| <a id="rce-d-8"></a>RCE-D-8 | **Verified on stable, with Miri deferred.** The engineer: "I don't care to take on the complexity of a nightly toolchain in CI if we can help it. ... I think we can at least defer for now." The crate's tests use a recording allocator that asserts every deallocation returns exactly the pointer and layout it handed out, counts allocations against frees, and poisons a freed block; sabotage entries cover the free condition and the counting. A decrement weakened from `Release`, or a missing `Acquire` fence, cannot be made to fail a test on a strongly ordered machine, so those entries are recorded as surviving, as documentation of what the tests cannot see. Undefined behaviour inside the `unsafe` blocks that shows as no wrong pointer, layout or count -- an aliasing violation -- is what Miri would add, parked as [RCE-inf.1](PARKED.md#m-inf----the-horizon). |
| <a id="rce-d-9"></a>RCE-D-9 | **A derivative work of the Rust standard library, credited as such.** The engineer: "this would be a derivative work, would be credited as such but would have its own destiny." The allocator interface (RCE-D-3) takes its names and signatures from the standard library, and the shared error's counting follows its `Arc`; a `NOTICE` file states it, with the standard library's MIT license text, which permits it under this workspace's MIT license. Linux's `kernel::sync::Arc` is credited for the idea of omitting weak references and nothing else: no code is taken from it. |
